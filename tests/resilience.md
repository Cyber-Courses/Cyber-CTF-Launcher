# What a player does that breaks a lab

The launcher runs labs on tools the player keeps using while a lab runs: Docker, Vagrant and a
hypervisor, a server, the computer itself. This is the catalogue of what a player (or the computer)
does to a lab outside the app, or to the app itself, at the worst moment, what the app must do
then, and which test holds it. A disruption is handled when the app:

- **recovers** where it can (a resume, a start again) or says plainly what happened and what to do;
- **lets the player retry or clean up** from the app, the next attempt clearing what the last one
  left;
- **leaves nothing behind**: no container, VM, network, file or launch token that no lab owns;
- **stays consistent after a restart**: what the lab page shows after the app is reopened is what
  is there.

## Where each is tested

| Tier                  | What it is                                                                                                                                                                                           | Runs                                       |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| **Isothrum unit**     | the runner against its fake engines: a Compose project modelled container by container, the fake Vagrant's VMs (`run/tests/disruptions*`, `driver/vagrant/tests/disruptions.rs`)                     | `cargo test` in Isothrum                   |
| **Isothrum property** | any sequence of operations and disruptions on the Compose model; every operation ends once, nothing reads ready that isn't, and `down` then `up` always bring the whole run back (`sequences.rs`)    | `cargo test` in Isothrum                   |
| **Launcher unit**     | the launcher's state and messages: the deploy worker's files, the lab page's view, the runner's failures in words                                                                                    | `cargo test --lib`, `vitest`               |
| **Integration**       | `resilience-*` in [integration/run.sh](integration/run.sh): the real Docker or hypervisor, the disruption done with the player's own tool ([testing/integration.md](../docs/testing/integration.md)) | here (Docker ones), the test rig (VM ones) |
| **Desktop**           | specs in [desktop/](desktop/) driving the real app: Stop during Start, a double Start, the window closed mid-start, the deploy worker killed                                                         | `pnpm test:desktop`, the rig               |
| **Rig only**          | what can't be done on a machine someone uses (sleep, reboot, a full disk, the network cut, Docker or a hypervisor stopped): behind `CYBERCTF_TEST_RESILIENCE_THROWAWAY=1` or proposed below          | the test rig's throwaway VMs               |

"Now" says what holds it today; **fixed** marks a bug these tests found, fixed with the test as its
regression; **gap** what isn't handled yet, with what would.

## The computer

## Found in the code

What the runner assumed nothing outside changed, and what now holds instead:

- **A record left mid-way** (A3): an operation records a moving state while it acts and settles it
  at its end, even when cut short in its process (`Unfinished`); a process killed never settled it.
  A record still moving with no operation holding the run now reads as failed, and the next
  operation settles it (Isothrum).
- **A resume trusted what it parked** (M1, M5): it ran the resume steps on whatever was left. It now
  reads the run first, refusing one with a machine gone (Isothrum).
- **The page hid what is gone** (M1): the view left out every absent machine, so a lab short of one
  looked healthy (launcher).
- **"No files" meant "nothing to stop"** (F1): a stop of a lab whose generated files were deleted
  removed nothing (launcher).
- **A worker's verdict was its own to write** (A3): one killed never wrote it (launcher).
- **Tools outlived a killed worker** (A4): each ran in a process group of its own, which the
  worker's death never reached. The runner now records them in the run's state while they run, and
  the next operation ends those a dead process left (Isothrum).
- **A Terraform run's status was its local state** (M10): a VM removed on the server read as
  running. The status now asks the server (Isothrum), with the server's credentials (launcher).
